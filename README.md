# 15_Node.js_service_deployment

## Project Overview

This repository contains the current infrastructure and configuration for deploying a Node.js Hello World service to an Oracle Cloud Infrastructure (OCI) virtual machine.

The implementation uses:
- Terraform for provisioning the OCI instance
- Ansible for server configuration and service deployment
- systemd to run the Node.js application as a service
- nginx as a reverse proxy to expose the app on port 80

## Roadmap Reference

- This project references the roadmap task: https://roadmap.sh/projects/nodejs-service-deployment
- The current repository covers manual Terraform and Ansible deployment.
- The repository uses OCI instead of the DigitalOcean example described in the roadmap.

## Project Structure

- `terraform/` — Terraform configuration for creating the OCI instance
- `ansible/` — Ansible playbook, inventory, and role definitions
- `nodejs_app_hello_world/` — Node.js application source code
- `orchestrator.sh` — script to run Terraform and generate Ansible inventory/SSH config

## What Gets Deployed

- One OCI compute instance named `staging_vm`
- Ubuntu-based server with installed packages: `git`, `ufw`, `vim`, `fail2ban`, `nodejs`, `npm`
- nginx as a reverse proxy
- systemd service `helloworld_nodeapp`
- Node.js application copied to `/www/nodejs_app_hello_world/`
- nginx proxying traffic to `127.0.0.1:8001`

## Ansible Components

The playbook `ansible/setup.yml` includes these roles:

- `base` — base server setup, OS updates, UFW firewall rules, fail2ban, Node.js and npm installation
- `nginx` — install nginx, deploy the site config, and enable nginx
- `app` — create the nodeapp user, copy the Node.js app, deploy the systemd unit, and start the app service

Additional repository files:

- `ansible/inventory.yaml` — host inventory generated by `orchestrator.sh`
- `ansible/ansible.cfg` — Ansible defaults for inventory and SSH private key

## Current Deployment Workflow

1. Provision infrastructure:
   - go to the `terraform` directory
   - update `terraform.tfvars` with your OCI values: compartment, subnet, image, SSH public key path, tenancy, user, private key, fingerprint
   - run:
     ```bash
     cd terraform
     terraform init
     terraform apply -auto-approve
     ```

2. Generate Ansible inventory and SSH config:
   - from the repository root run:
     ```bash
     ./orchestrator.sh
     ```
   - the script:
     - applies Terraform
     - reads the instance public IP and name from Terraform outputs
     - writes `ansible/inventory.yaml`
     - writes SSH config in `~/.ssh/config.d`

3. Apply the Ansible playbook:
   - go to the `ansible` directory
   - run:
     ```bash
     cd ansible
     ansible-playbook setup.yml
     ```

4. Run specific roles with tags:
   - `ansible-playbook setup.yml --tags base`
   - `ansible-playbook setup.yml --tags nginx`
   - `ansible-playbook setup.yml --tags app`

## Node.js Application

The `nodejs_app_hello_world/` folder contains:
- `index.js` — a simple Node.js HTTP server listening on port `8001`
- `package.json` — application metadata and start command

The `app` role copies this folder to the server under `/www/` and deploys the `helloworld_nodeapp` systemd service.

## nginx

The file `ansible/nginx/templates/nginx.conf.j2` configures nginx to proxy requests from port `80` to the Node.js app on `127.0.0.1:8001`.

## Useful Commands

- Provision infrastructure with Terraform:
  ```bash
  cd terraform
  terraform apply -auto-approve
  ```
- Generate inventory and SSH config:
  ```bash
  ./orchestrator.sh
  ```
- Run the Ansible playbook:
  ```bash
  cd ansible
  ansible-playbook setup.yml
  ```
- Restart services if needed:
  ```bash
  ssh ubuntu@<IP>
  sudo systemctl restart helloworld_nodeapp
  sudo systemctl restart nginx
  ```

## Verification and Access

- The Node.js application runs as the `helloworld_nodeapp` systemd service
- nginx proxies traffic to the Node.js app on port `8001`
- the public IP address comes from Terraform output `public-ip-for-compute-instance`

## Notes

- `ansible/ansible.cfg` sets the default inventory and SSH private key file.
- `terraform/outputs.tf` includes the instance public IP and name outputs.
- This repository does not contain a GitHub Actions workflow for deployment.
- The current configuration is built for manual deployment via Terraform and Ansible.
